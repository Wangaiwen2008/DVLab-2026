任务一：环境配置与工具链说明文档
 
一、 笔记必答问题复盘
 
1. 你是如何判断自己应该安装哪个版本的 PyTorch 的？
 
我使用的是华硕天选6Pro笔记本电脑。首先，我确认了电脑带有独立显卡（NVIDIA）。接着，我在终端运行了 nvidia-smi 命令，查看了当前显卡驱动支持的 CUDA 版本。随后，我访问了 PyTorch 官方网站，在安装向导中选择 Windows 系统、Conda 包管理器以及对应的 CUDA 版本，复制了官网生成的专属安装命令进行安装。安装完成后，我运行 import torch 并打印 torch.cuda.is_available()，返回 True 证明 GPU 版本安装成功且可用。
 
2. 在此过程中遇到了什么报错？你是如何解决的？（排查思路复盘）
 
在整个环境搭建和代码提交过程中，我遇到了几个典型的报错，排查与解决过程如下：
• 报错 1：终端找不到 conda 或 git 命令（提示 'xxx' 不是内部或外部命令）
	• 排查思路：首先意识到可能是软件安装时未正确配置系统环境变量（PATH），或者当前终端窗口未更新最新配置。
	• 解决办法：对于 Git，我重新运行安装包，在 Adjusting your PATH environment 步骤中，明确选中了 Git from the command line and also from 3rd-party software。安装完毕后，彻底关闭并重启了终端，再次测试成功。
• 报错 2：Git 提交命令格式错误导致推送失败
	• 排查思路：执行 git commit -m 时漏掉了后面的引号和说明文字，报错 switch 'm' requires a value，进而导致 git push 失败（src refspec main does not match any）。
	• 解决办法：明确 -m 参数后必须紧跟规范的提交描述。补齐完整的双引号内容后，重新 commit 并 push，成功将文件上传至云端。
• 报错 3：文件扩展名隐藏导致文件类型错误
	• 排查思路：新建文档后发现文件类型依然是文本文档（TXT），而不是 Markdown（MD）。
	• 解决办法：在 Windows 文件夹的“查看”菜单中，勾选“文件扩展名”，手动重命名删掉了多余的 .txt 后缀。
• 报错 4：GitHub 网页访问超时与 DNS 劫持
	• 排查思路：终端 git push 显示成功，但浏览器打不开网页，甚至跳转到虚假网站。经分析，终端与网页的通信链路不同，网页端遭遇了运营商 DNS 劫持。
	• 解决办法：后续在学长的指导下成功恢复了网页端的正常访问。 
 
二、 任务执行过程与 AI 协作记录
 
在本次任务中，我结合使用了豆包和deepseek来协助学习和排错。具体过程如下：
 
1. 环境与 Git 安装
借助 AI 的指导，我挑选了合适版本的 Git 安装程序，并成功安装了 Miniconda。面对 Git 下载被浏览器拦截的问题，我确认安全源后解除了拦截。
 
2. 核心命令与危险操作规避
在编写 git commit、git push 命令时，AI 提醒我规范的命令格式。特别是在遇到推送报错时，AI 曾建议使用 git push -f 强制推送，但我经过分析后意识到，报错是因为本地还没有成功 commit，本地根本没有记录，盲目强制推送具有覆盖丢失代码的风险。我通过补齐 commit 解决了问题，避免了危险操作。
 
3. 解决网络与底层逻辑问题
遇到网页打不开但终端能推送成功的奇怪现象时，AI 帮我区分了「终端 git 推送（底层协议）」和「浏览器网页访问（HTTP/HTTPS）」的区别，解释了 DNS 劫持造成的影响差异，让我没有陷入无效排查。
 
4. 环境验证
AI 告诉我怎么通过 nvidia-smi 查看 CUDA 版本、怎么挑选适配华硕天选6Pro 的 GPU 版 PyTorch，并给出了 torch.cuda.is_available() 的验证方案。
